# Kilo/Roo 自定义模式管家

> 一个地方管理，多个 IDE 同步 —— 让你的 AI 编程助手配置井井有条

---

## 为什么需要这个工具？

如果你同时使用多个 IDE（VS Code、Trae、Cursor、Windsurf 等），并且在每个 IDE 中都安装了 KiloCode 或 RooCode 插件，你可能遇到过这些烦恼：

- 🔄 **重复劳动**：在每个 IDE 中都要手动配置一遍自定义模式
- 😵 **配置混乱**：不同 IDE 的模式配置不一致，不知道哪个是最新版本
- 📝 **难以分享**：看到 GitHub 上的优质模式配置，需要手动复制粘贴到每个 IDE
- ⏰ **浪费时间**：每次调整模式配置，都要在多个 IDE 中重复操作

**这个工具就是为了解决这些问题而生。**

---

## 它能帮你做什么？

### 📦 统一管理
在一个地方管理所有自定义模式，不再需要在多个 IDE 之间来回切换。

### 🔄 一键同步
修改一次，同步到所有 IDE。支持选择性同步，你可以决定哪些 IDE 需要更新。

### 🌐 GitHub 导入
从 GitHub 搜索并导入优质的自定义模式配置，站在巨人的肩膀上。

### 📊 差异对比
清楚地看到本地库和各个 IDE 之间的配置差异，决定是导入新增模式还是写回统一版本。

### 🕐 历史追溯
记录每次写回操作的历史，可以随时回放到之前的版本。

### 🔍 质量筛选
根据模式的详细程度（roleDefinition 长度）自动筛选高质量模式。

## 核心功能一览

### 1. 库管理
- 查看所有本地模式，按来源（本地、GitHub、IDE）分类
- 按质量阈值筛选高质量模式
- 编辑、克隆、删除模式
- 批量导入 YAML/JSON 配置

### 2. IDE 配置
- 自动扫描本机所有 IDE 的配置文件
- 手动添加自定义路径
- 勾选需要同步的目标 IDE
- 查看每个 IDE 的当前生效模式

### 3. GitHub 同步
- 配置搜索规则（支持多条规则并行执行）
- 一键同步所有启用规则
- 查看同步记录和错误日志
- 支持代理和延时控制

### 4. 差异检查
- 对比本地库与 IDE 配置的差异
- 识别"IDE 新增"、"同名冲突"、"本地库独有"三种情况
- 提供针对性的处理建议（导入、写回、忽略）

### 5. 历史回放
- 记录每次写回操作的前后状态
- 支持一键回放到历史版本
- 查看操作统计和时间线

### 6. 模式对比
- 跨软件对比（KiloCode vs RooCode）
- 识别缺失的模式
- 一键补齐到目标类型

## 快速开始

### 第一步：扫描 IDE 实例
打开应用后，前往"IDE 配置"页面，点击"扫描白名单路径"，自动识别本机所有 IDE 的配置文件。

### 第二步：导入现有模式
前往"库管理"页面，点击"批量导入"，粘贴你现有的 YAML 配置，或者从 IDE 实例中扫描导入。

### 第三步：配置 GitHub 同步（可选）
前往"设置"页面，配置 GitHub Token 和代理（如需要），然后在"GitHub 同步"页面添加搜索规则。

### 第四步：同步到 IDE
在"库管理"页面选择要同步的模式，点击"同步"，勾选目标 IDE，一键写入。

## 常见问题

### Q: 这个工具会修改我的 IDE 配置文件吗？
A: 是的，当你执行"同步到 IDE"操作时，工具会修改对应 IDE 的 `custom_modes.yaml` 文件。但每次修改前都会记录历史，你可以随时回滚。

### Q: 支持哪些 IDE？
A: 支持所有使用 KiloCode 或 RooCode 插件的 IDE，包括但不限于：VS Code、Trae、Cursor、Windsurf、CodeBuddy 等。

### Q: GitHub 同步需要什么权限？
A: 需要一个 GitHub Personal Access Token，权限只需要 `public_repo`（读取公开仓库）即可。

### Q: 如何在多台电脑之间同步配置？
A: 在"设置"页面导出备份文件，然后在另一台电脑上导入即可。

### Q: 会不会覆盖掉我现有的配置？
A: 工具提供三种冲突处理策略：
- **覆盖**：用新配置替换同名配置
- **重命名**：自动为新配置添加后缀（如 `-v2`）
- **跳过**：保留现有配置，不导入新配置

你可以根据需要选择合适的策略。

## 使用建议

### 建议的工作流程
1. **首次使用**：扫描所有 IDE 实例，将现有配置导入本地库
2. **日常使用**：在本地库中统一管理和编辑模式
3. **定期同步**：定期检查差异，将本地库同步到各个 IDE
4. **探索新模式**：通过 GitHub 同步发现和导入优质模式
5. **定期备份**：每月导出一次备份文件，以防数据丢失

### 最佳实践
- ✅ 为每个 IDE 实例设置有意义的别名（如"Trae - 前端开发"）
- ✅ 定期清理不再使用的模式，保持库的整洁
- ✅ 使用质量阈值筛选，优先使用高质量模式
- ✅ 在写回前先检查差异，避免误覆盖
- ✅ 重要操作前先导出备份
